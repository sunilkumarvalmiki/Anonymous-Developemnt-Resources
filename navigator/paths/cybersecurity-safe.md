# Learn Cybersecurity Safely

[Back to Resource Navigator](../README.md)

## Who This Is For

Use this path if you want defensive security knowledge, safer web applications, and lawful lab-style learning.

## Outcome

You should finish with a defensive checklist and enough vocabulary to identify common web risks without crossing legal or ethical boundaries.

## First Three Resources

- [OWASP Top 10](https://owasp.org/www-project-top-ten/) - Start with the common web application risk categories.
- [OWASP Cheat Sheet Series](https://cheatsheetseries.owasp.org/) - Use defensive implementation guidance for real application decisions.
- [Awesome Web Security](https://github.com/qazbnm456/awesome-web-security) - Expand into web security tools and learning material.

## Next Resources

- [Awesome OSINT](https://github.com/jivoi/awesome-osint) - Study lawful open-source intelligence tools and sources.
- [HackTricks](https://book.hacktricks.wiki/) - Use lab-oriented notes carefully for understanding attacker techniques and defensive exposure checks.
- [GitHub Skills](https://skills.github.com/) - Strengthen GitHub workflow basics for security-focused collaboration.
- [Developer Roadmaps](https://roadmap.sh/) - Compare security role paths and prerequisite topics.
- [Public APIs](https://github.com/public-apis/public-apis) - Build harmless practice projects around public data and API handling.

## Deep Dives

- [System Design Primer](https://github.com/donnemartin/system-design-primer) - Learn architecture tradeoffs that affect security decisions.
- [Docker Docs](https://docs.docker.com/) - Use containers to isolate labs and local services.

## Skip Until Later

- Testing systems you do not own or have explicit permission to assess.
- Malware, credential theft, exploit trading, or anything that bypasses consent.

## Practice Checkpoint

Review a demo application against OWASP guidance and write a defensive checklist with risks, fixes, and verification steps.
