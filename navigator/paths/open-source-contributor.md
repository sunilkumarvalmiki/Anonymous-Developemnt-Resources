# Contribute to Open Source

[Back to Resource Navigator](../README.md)

## Who This Is For

Use this path if you want to make useful public contributions without overwhelming maintainers or yourself.

## Outcome

You should finish with a small merged or review-ready pull request and a better understanding of project contribution rules.

## First Three Resources

- [First Contributions](https://github.com/firstcontributions/first-contributions) - Practice the basic pull request workflow in a guided beginner project.
- [GitHub Skills](https://skills.github.com/) - Learn GitHub workflows through interactive exercises.
- [Open Source Guides](https://opensource.guide/) - Learn contribution norms, maintainer expectations, and community basics.

## Next Resources

- [Good First Issue](https://goodfirstissue.dev/) - Search beginner-friendly issues across repositories.
- [Awesome for Beginners](https://github.com/MunGell/awesome-for-beginners) - Find projects with beginner-friendly issue labels.
- [Git Cheat Sheet](https://training.github.com/downloads/github-git-cheat-sheet/) - Reference common Git commands during contribution work.
- [Awesome README](https://github.com/matiassingers/awesome-readme) - Learn how strong documentation helps open source projects.
- [Developer Roadmaps](https://roadmap.sh/) - Choose contribution targets aligned with your learning direction.

## Deep Dives

- [Awesome Actions](https://github.com/sdras/awesome-actions) - Learn workflow automation patterns that can improve repositories.
- [Awesome CLI Apps](https://github.com/agarrharr/awesome-cli-apps) - Study useful command-line projects and tooling ideas.

## Skip Until Later

- Rewriting project architecture as a first contribution.
- Drive-by pull requests that ignore maintainers' contribution rules.

## Practice Checkpoint

Open one small, scoped pull request with a clear description, validation notes, and respectful follow-up on review feedback.
