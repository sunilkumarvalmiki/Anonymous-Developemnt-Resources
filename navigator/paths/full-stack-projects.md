# Build Full-Stack Projects

[Back to Resource Navigator](../README.md)

## Who This Is For

Use this path if you know some frontend or backend basics and want to ship complete projects.

## Outcome

You should finish with one public project that has a real workflow, persistent data, validation, deployment, and readable documentation.

## First Three Resources

- [The Odin Project](https://www.theodinproject.com/) - Use the project-based structure to connect frontend, backend, Git, and databases.
- [Full Stack Open](https://fullstackopen.com/en/) - Learn modern React, Node.js, testing, TypeScript, and deployment patterns.
- [Public APIs](https://github.com/public-apis/public-apis) - Pick an API that gives the project real data and a reason to exist.

## Next Resources

- [Next.js Docs](https://nextjs.org/docs) - Use this for full-stack React applications and deployment-ready routing patterns.
- [Node.js Learn](https://nodejs.org/en/learn) - Review backend JavaScript fundamentals when building server logic.
- [PostgreSQL Docs](https://www.postgresql.org/docs/) - Use a relational database for persistent application data.
- [Vercel Docs](https://vercel.com/docs) - Deploy web applications with previews and framework support.
- [Netlify Docs](https://docs.netlify.com/) - Compare another deployment workflow for static and full-stack sites.

## Deep Dives

- [Cloudflare Pages Docs](https://developers.cloudflare.com/pages/) - Learn edge-oriented static and full-stack deployment options.
- [GitHub Actions Docs](https://docs.github.com/en/actions) - Add automated validation and deployment steps.
- [Docker Docs](https://docs.docker.com/) - Standardize local development and service dependencies.
- [Awesome README](https://github.com/matiassingers/awesome-readme) - Improve project documentation and presentation.

## Skip Until Later

- Complex SaaS billing, permissions, and multi-tenant architecture.
- Copying tutorial apps without changing the data model, UI, or workflow.

## Practice Checkpoint

Ship one public project with authentication-ready structure, persistent data, CI validation, deployment, and a clear demo path.
